# Contribution lifecycle

1. Propose a small public-safe issue; agree on acceptance criteria and ownership.
2. Prepare a local branch; preserve existing history and unrelated changes.
3. Implement and test. Use synthetic examples, record actual results and limitations.
4. Review the exact diff and security scan outcomes; unresolved findings block publication.
5. Obtain owner publication approval, then submit a focused PR with reproducible evidence.
6. Reviewers check behavior, architecture, provenance and license compatibility.
7. Resolve feedback through new commits; do not rewrite historical commits here.
8. Owner-authorized merge records the accepted change. A closed unmerged PR is not
   an accepted contribution. No guaranteed review/merge schedule is implied.
9. Offer optional attribution only after acceptance and separate consent review.
10. Correct or withdraw attribution when requested; retain only a privacy-safe tombstone.

A rejection or withdrawal is not an endorsement, award or verified impact event.
The workflow is documented governance, not an implemented GitHub automation.
