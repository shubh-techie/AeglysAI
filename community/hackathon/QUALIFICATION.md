# Mandatory AeglysAI qualification

REGISTER → FORK AEGLYSAI → CLONE & RUN BASELINE → UNDERSTAND & DOCUMENT → SUBMIT SANITIZED QUALIFICATION EVIDENCE → ORGANIZER REVIEW → SELECTION → BUILD & COMPETE

1. REGISTER using the official Google Form. Organizer-owned registration, qualification and final-submission Form URLs are PENDING CONFIGURATION; no unofficial link substitutes for them. This repository does not announce an open registration event.
2. FORK AEGLYSAI: fork https://github.com/shubh-techie/AeglysAI using your GitHub account.
3. CLONE AND RUN: clone your fork and demonstrate a working baseline using the repository's documented .NET 8 setup, restore, build and tests. Record the exact commit, commands, environment and actual outcomes; report failures honestly.
4. UNDERSTAND AND DOCUMENT: document architecture, setup, one observation, one proposed improvement and validation results. A/B/C baseline understanding is sufficient; Model D knowledge is not required.
5. SUBMIT QUALIFICATION EVIDENCE through the organizer-designated official Google Form: registration ID, GitHub username, fork URL, qualification branch URL, qualification document URL, architecture understanding, one observation, one proposed improvement and sanitized build/run/test evidence. Keep registration identifiers and their participant association in private administration records, outside public Git. Use the [qualification document template](templates/QUALIFICATION.md) for public technical evidence.
6. ORGANIZER REVIEW: check eligibility against published event rules, registration match, official fork provenance, branch/commit, working baseline, document completeness and sanitized evidence. Record review and corrections privately. Eligibility rules and deadlines require organizer publication before opening registration.
7. SELECTION: notify selected competitors privately under published capacity criteria. Qualification does not guarantee selection. No unreviewed applicant is automatically selected.
8. BUILD AND COMPETE: selected competitors choose one of the six approved tracks and follow the competition submission contract. The final challenge may use any programming language; AeglysAI integration is optional. Qualification remains mandatory.

Do not publish private participant data or confidential invention material. An unavailable prerequisite or failed command is an organizer review issue, not permission to skip qualification.

Every participant, including the team lead, must complete individual prequalification. No team member may bypass qualification based on another member's results. Eligibility review and individual selection are separate from competition scoring. A team may enter only when every active member is qualified and selected. See [team rules](TEAMS.md).
